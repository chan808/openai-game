# Development Log

기술 방향, 스코프와 플레이테스트에서 확정한 굵직한 판단만 남기는 기록이다. 대회 제출 문안이나 상세 작업 일지로 사용하지 않는다.

## 기록 원칙

- 매일 또는 모든 커밋마다 쓰지 않는다. 되돌리기 비용이 큰 기술 결정, 스코프 변경이나 플레이테스트 판단이 확정됐을 때만 추가한다.
- 계획이나 예상 성과 대신 실제 변경, 사용자 판단, 검증 결과를 기록한다.
- 한 항목은 3~5줄로 작성하고, 남길 내용이 없는 줄은 생략한다.
- 커밋을 만든 뒤 식별 가능한 짧은 해시를 적는다.

## 작성 형식

### YYYY-MM-DD — 작업 단위

- Commit: `<short hash>`
- Codex 작업: 변경하거나 제안한 핵심
- 사용자 판단: 플레이테스트나 검토 뒤 사용자가 확정한 내용
- 설계 이유: 다른 작업에서도 알아야 할 핵심 근거
- 검증: 실행한 테스트와 결과
- 남은 쟁점: 다음 작업에 실제로 영향을 주는 항목만 기록

## 기록

### 2026-08-19 — 공유 시야와 탐색 행동

- Commit: `6c722f8`
- 사용자 판단: 적은 진입 즉시 추격하지 않고 진형을 유지하며, 한 적이 플레이어를 보면 마지막 목격 위치를 공유해 교전·탐색한 뒤 발견하지 못하면 원래 자리로 복귀한다.
- 설계 이유: 검병은 공유 목표를 향해 기둥을 우회하고 궁병은 사선과 선호 거리를 함께 확보하되, 완전한 은신 시스템이나 범용 경로 탐색은 추가하지 않았다.
- 검증: 59개 테스트와 프로덕션 빌드가 통과했고, 브라우저에서 `holding`→`engaged` 전환과 두 병과의 이동 및 콘솔 오류 없음을 확인했다.
- 남은 쟁점: 탐색 지속 시간과 궁병 재배치 빈도가 실제 플레이에서 과하거나 느슨한지 조정한다.

### 2026-08-19 — 피격 반응과 준비된 적 진형

- Commit: `acf5076`
- 사용자 판단: 플레이어 피격에는 짧은 무적·주변 적 넉백·약한 화면 흔들림을 주고, 적은 스테이지 진입부터 전방 검병과 후방 궁병 진형을 유지한다.
- 설계 이유: 한 번의 피격으로 진형을 무너뜨리지 않고 `holding`, `pressing`, `broken` 단계와 고정 거점만 추가해 기존 개별 AI를 그대로 재사용한다.
- 검증: 55개 테스트와 프로덕션 빌드가 통과했고, 브라우저에서 시작 진형과 전투선 진입 후 전진 전환 및 콘솔 오류 없음을 확인했다.
- 남은 쟁점: 궁병의 첫 사격 압박, 진형 전투선과 거점 위치가 실제 플레이에서 자연스러운지 조정한다.

### 2026-08-18 — 단일 화면 지형 검증 시작

- Commit: `2e5ffa0`

- 설계 이유: 새 진행 시스템 없이 사선 차단, 우회와 순간이동 진입각이 기존 무기 선택과 위치 판단을 늘리는지 분리해서 확인한다.
- 검증: 순수 TypeScript 지형 판정 49개 테스트와 프로덕션 빌드가 통과했고, 브라우저에서 배치와 예고선 차단 및 콘솔 오류 없음을 확인했다.
- 남은 쟁점: 한 화면이 답답한지 플레이한 뒤 화면보다 큰 맵과 다음 층 적 조합 중 다음 검증 대상을 정한다.
