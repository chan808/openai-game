# Development Log

기술 방향, 스코프와 플레이테스트에서 확정한 굵직한 판단만 남기는 기록이다. 대회 제출 문안이나 상세 작업 일지로 사용하지 않는다.

## 기록 원칙

- 매일 또는 모든 커밋마다 쓰지 않는다. 되돌리기 비용이 큰 기술 결정, 스코프 변경이나 플레이테스트 판단이 확정됐을 때만 추가한다.
- 계획이나 예상 성과 대신 실제 변경, 사용자 판단, 검증 결과를 기록한다.
- 한 항목은 3~5줄로 작성하고, 남길 내용이 없는 줄은 생략한다.
- 커밋을 만든 뒤 식별 가능한 짧은 해시를 적는다.

## 작성 형식

### YYYY-MM-DD — 작업 단위

- Commit: `<short hash>`
- Codex 작업: 변경하거나 제안한 핵심
- 사용자 판단: 플레이테스트나 검토 뒤 사용자가 확정한 내용
- 설계 이유: 다른 작업에서도 알아야 할 핵심 근거
- 검증: 실행한 테스트와 결과
- 남은 쟁점: 다음 작업에 실제로 영향을 주는 항목만 기록
