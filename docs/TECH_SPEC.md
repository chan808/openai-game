# ECHO — Technical Constraints

이 문서는 첫 프로토타입부터 반드시 지켜야 하는 기술 경계만 정의한다. 아직 플레이로 검증하지 않은 게임 시스템의 상세 설계는 포함하지 않는다.

## 스택

- Node.js 22.12+
- TypeScript strict
- Vite
- Phaser 4.2.1
- Vitest
- 정적 웹 빌드

Phaser는 반드시 `4.2.1`로 정확히 고정한다. 설치와 스모크 테스트가 끝나기 전에는 게임 로직을 구현하지 않는다.

## 절대 규칙

1. 게임 로직은 60Hz 고정 타임스텝으로만 진행한다.
2. Phaser Arcade/Matter Physics를 사용하지 않는다.
3. Phaser는 presentation 계층에서 렌더링, 브라우저 입력, 카메라, 오디오와 이펙트만 담당한다.
4. 이동·공격·충돌 상태는 순수 TypeScript 데이터와 함수로 처리한다.
5. 액터는 키보드와 마우스를 직접 읽지 않고 `InputSource`만 받는다.
6. 플레이테스트로 조정할 게임필 수치는 `src/content/tuning.ts`에 둔다. 기술 상수는 담당 모듈에 이름을 붙여 둔다.
7. 네트워크, 저장소, 플랫폼 인터페이스는 실제로 필요해질 때까지 만들지 않는다.

## 첫 프로토타입 구조

처음부터 최종 폴더 구조를 만들지 않는다. 첫 동작에 필요한 파일만 생성한다.

```text
src/
  main.ts
  core/
    GameClock.ts
    GameClock.test.ts
    InputSource.ts
  game/
    actorCollision.ts
    GameState.ts
    archer.ts
    enemies.ts
    enemyState.ts
    longsword.ts
    playerDamage.ts
    projectiles.ts
    teleport.ts
    terrain.ts
    ultimate.ts
    updateGame.ts
  presentation/
    ArenaScene.ts
    PhaserInputSource.ts
    SkillBindings.ts
    SkillLoadoutUi.ts
  content/
    tuning.ts
```

- `core`와 `game`은 Phaser, DOM, 브라우저 이벤트를 import하지 않는다.
- `presentation`이 Phaser API를 담당한다. `main.ts`는 Phaser 부트스트랩과 의존성 조립만 하며 게임 규칙을 갖지 않는다.
- 실제 기능이 생길 때만 파일을 분리한다.

## 고정 타임스텝

Phaser의 렌더 프레임 경과시간은 `GameClock` 누적기에만 전달한다. 게임 업데이트는 `GameClock`이 생성한 고정 스텝으로 실행한다.

```ts
interface SimulationStep {
  frame: number;
  dt: number;
}
```

- 한 렌더 프레임에서 실행할 최대 catch-up 횟수를 제한한다.
- 탭 복귀 후 남은 과도한 누적시간은 버린다.
- `Date.now()`, `performance.now()`, `requestAnimationFrame` 델타를 게임 규칙에서 직접 읽지 않는다.
- 첫 테스트는 정상 프레임, 긴 프레임, catch-up 제한을 검증한다.

타격감용 히트스톱은 적중이 확정되면 대상의 상태에 남은 프레임 수를 기록한다. 롱소드는 공격자와 피격 대상을 함께 멈추고, 원거리 투사체는 피격 대상만 멈춘다. 해당 대상의 이동과 행동 타이머만 멈추며 `GameClock`, 시뮬레이션 프레임과 입력 샘플링은 계속 진행한다. 지속 시간은 `src/content/tuning.ts`에서 조정하고 네트워크나 범용 시간 시스템은 미리 만들지 않는다.

## 입력 모델

첫 프로토타입은 동작의 의미만 표현하고 실제 키는 어댑터가 결정한다.

```ts
interface InputFrame {
  moveX: number;
  moveY: number;
  aimTargetX: number;
  aimTargetY: number;
  primaryPressed: boolean;
  teleportPressed: boolean;
  ultimatePressed: boolean;
  weaponSlotPressed: 0 | 1 | 2 | null;
}

interface InputSource {
  sample(frame: number): InputFrame;
}
```

- `moveX`, `moveY`는 정규화된 이동 방향이다.
- `aimTargetX`, `aimTargetY`는 현재 커서의 게임 월드 좌표다. 플레이어 조준과 유도 마법의 회전은 게임 로직이 이 좌표에서 계산한다.
- `primaryPressed`는 브라우저 입력의 상승 에지를 어댑터가 보관했다가 다음 시뮬레이션 틱에서 한 번만 반환하고 즉시 비운다.
- `teleportPressed`는 커서 방향 순간이동을 시도하는 상승 에지다.
- `ultimatePressed`는 충전된 시간정지 궁극기를 시도하거나 기록 중 조기 재생을 요청하는 상승 에지다.
- `weaponSlotPressed`는 실제 숫자 키가 아니라 플레이테스트 슬롯 ID다. 실제 키 배정은 입력 어댑터에만 둔다.
- 플레이어 히트스톱 중 들어온 `primaryPressed`와 `teleportPressed`는 게임 상태가 정해진 고정 프레임 동안 한 번씩 보존하고, 해당 행동이 가능해지면 한 번만 소비한다. 보존 시간은 `src/content/tuning.ts`에서 조정한다.
- 한 렌더 프레임에서 여러 catch-up 틱이 실행되어도 클릭 한 번이 여러 공격으로 소비되면 안 된다.
- Q, E, R, Space와 마우스 오른쪽 버튼의 스킬 배치는 presentation 계층의 `SkillBindings`가 관리한다.
- 기본 배치는 R에 시간정지, 마우스 오른쪽 버튼에 순간이동이며 Q, E, Space는 비어 있다.
- 스킬창이 열린 동안 `PhaserInputSource`는 게임플레이 입력을 만들지 않는다.

이 형태는 나중에 로컬 입력을 녹화하거나 네트워크 입력으로 교체할 수 있게 하지만, 지금 범용 입력 리플레이나 네트워크 구현을 요구하지 않는다.

## 현재 게임 상태

첫 프로토타입 상태는 다음 정보만 가진다.

- 플레이어 위치와 조준 방향
- 플레이어의 현재·최대 HP, 피격 횟수와 남은 무적 프레임
- 안정적인 ID와 종류를 가진 검병·궁병의 위치, HP, 조준 방향, 행동 단계, 피격 표시와 넉백의 남은 프레임 및 궁병이 유지 중인 전술 각도
- 검병·궁병 조합의 공유 인식 단계, 마지막 목격 위치, 수색 타이머와 확인한 누적 피격 횟수
- 선택한 무기 슬롯과 각 기본 공격의 쿨다운
- 히트스톱 중 보존한 기본 공격과 순간이동 입력의 남은 프레임
- 롱소드 기본 공격의 고정 조준 방향과 남은 스윙 프레임
- 안정적인 ID, 종류, 위치, 속도와 남은 프레임을 가진 화살·마법 투사체
- 순간이동 목적지, 남은 쿨타임과 출발 잔상의 위치·남은 프레임
- 시간정지 궁극기의 충전량, 현재 단계, 남은 프레임, 기록한 플레이어 위치·조준·무기 공격·투사체 상태와 보류한 적중 이벤트
- 현재 시뮬레이션 프레임

방패병과 마법사 상태, 장비 드롭, 스테이지 해금, 경험치, 층, 보스와 적응 통계 필드는 아직 추가하지 않는다.

## 검병

- 교전 중 검병은 부대가 공유한 현재 또는 마지막 목격 위치를 추적한다. 시야가 끊기면 해당 위치까지 이동해 수색한다.
- 대기 또는 복귀 중에는 처음 전방 거점으로 이동한다. 플레이어를 다시 목격하면 즉시 교전으로 전환한다.
- 플레이어를 직접 볼 수 있고 사거리 안에 있을 때만 공격 방향을 고정하고 예고, 베기와 후딜레이를 순서대로 실행한다.
- 예고를 시작하면 공격 방향을 다시 추적하지 않고 후딜레이가 끝날 때까지 자발적 이동을 멈춰, 회피 가능한 커밋 공격과 반격 시간을 만든다.
- 이동과 행동 타이머는 히트스톱 또는 시간정지 중 멈춘다.
- 베기는 화면에 표시한 고정 방향 선분과 플레이어의 원 충돌체를 직접 비교하고 한 공격에 한 번만 피해를 준다.
- 고정된 베기가 플레이어를 빗나가고 활성 순간이동 잔상과 겹치면 공격을 잔상에 소비하고 궁극기 충전량을 얻는다.
- 플레이어 공격은 무기별 임시 피해량만큼 검병 HP를 줄인다. HP가 소진된 검병은 짧은 월드 시간 뒤 재등장한다.
- 플레이어가 실제 피해를 받으면 짧은 무적을 시작하고 일정 반경의 살아 있는 적을 몇 프레임 동안 바깥으로 밀어낸다. 넉백 이동도 순수 TypeScript 지형 판정을 적용한다.
- 무적 중 들어온 공격은 HP, 피격 횟수와 피격 반응을 다시 갱신하지 않는다. 카메라 흔들림은 피격 횟수 증가를 presentation 계층이 감지해 한 번만 재생한다.
- 플레이어 HP가 소진되면 시작 위치와 최대 HP로 즉시 복귀하고 패배 횟수를 기록한다. 게임 오버 UI는 아직 만들지 않는다.

## 궁병

- 교전 중 궁병은 현재 방위를 기준으로 공유된 플레이어 위치 주변에서 사선이 열리고 선호 거리 구간에 들어오는 전술 각도를 선택한다. 선택한 각도가 유효한 동안 유지하고 지형 침범이나 사선 상실 때만 다시 선택해 목표 지점 진동을 막는다.
- 플레이어를 직접 볼 수 있고 현재 위치가 선호 거리 구간이며 실제 화살 경로가 열렸을 때만 공격을 준비한다.
- 수색 중에는 마지막 목격 위치를 볼 수 있는 지점으로 이동하되 공격하지 않으며, 복귀 중에는 처음 후방 거점으로 돌아간다.
- 공격 준비를 시작한 틱의 방향을 고정하고 실제 화살 경로에 반투명 잔상을 표시한다. 준비 시간이 끝나면 플레이어 활과 같은 속도·수명의 직선 화살을 발사한다.
- 궁병 화살은 적 소유 투사체로 구분해 플레이어 또는 활성 순간이동 잔상과 충돌하며, 시간정지 중에는 위치와 수명이 멈춘다.
- 이미 발사된 궁병 화살이 플레이어를 빗나가고 활성 순간이동 잔상과 충돌해도 공격을 잔상에 소비하고 궁극기 충전량을 얻는다.
- 발사 후에는 고정된 후딜레이를 거친 뒤 다시 거리 조절을 시작한다. 이동, 준비와 후딜레이는 히트스톱 중 멈춘다.
- 방패병과 마법사 행동은 만들지 않는다. 적 상태는 `kind`로 구분한 유니온과 안정적인 ID 배열로 갱신해 이후 실제 적 종류가 추가될 때 분기 하나를 확장할 수 있게 둔다.

## 검병·궁병 공유 인식과 이동

- 부대는 `holding`, `engaged`, `searching`, `returning` 네 단계와 하나의 마지막 목격 위치를 공유한다.
- 시야 거리는 별도로 제한하지 않고 기둥과 벽에 가리지 않는지만 순수 TypeScript 선분 판정으로 확인한다. 살아 있는 적 하나라도 플레이어를 보면 현재 위치를 공유하고 `engaged`가 된다.
- 플레이어 공격에 맞은 경우에도 공격 위치가 드러난 것으로 취급해 `engaged`가 된다. 한 번의 피격이나 넉백으로 부대 행동이 와해되지는 않는다.
- 모든 적이 플레이어를 놓치면 `searching`으로 바뀐다. 검병이 마지막 목격 위치에 도달한 뒤 짧은 확인 시간이 끝나면 `returning`으로 전환하고, 두 적이 처음 거점에 도착하면 `holding`으로 돌아간다.
- 검병과 궁병은 직접 이동선이 기둥에 막히면 현재 맵 중앙의 고정 웨이포인트 그래프에서 가장 짧은 경로를 사용한다. 범용 스테이지 길찾기, 시야각, 청각, 의심 게이지와 무작위 수색은 만들지 않는다.
- 처음 거점, 수색 시간과 웨이포인트는 `src/content/tuning.ts`에서 조정한다.

## 순간이동

- 커서 방향으로 순간이동할 수 있다.
- 이동 거리는 상한을 가지며 벽, 기둥과 살아 있는 적의 충돌체 내부에 착지하지 않는다.
- 기둥은 넘어갈 수 있지만 사방 벽 바깥으로 이동할 수는 없다.
- 쿨타임은 플레이어 행동 타이머이므로 시간정지 중에도 정상 진행하고, 히트스톱 중에는 멈춘다.
- 최대 거리와 기본 쿨타임은 `src/content/tuning.ts`에서 조정한다.
- 사용하면 출발 위치에 플레이어 크기의 잔상을 고정 프레임 동안 남긴다. 새 잔상을 만들면 기존 잔상을 대체한다.
- 고정된 검병 베기 또는 이미 발사된 궁병 화살이 플레이어 대신 잔상에 처음 적중하면 잔상을 소비하고 궁극기 충전량을 한 번만 더한다.
- 플레이어 공격 적중은 순간이동 쿨타임을 초기화하지 않는다.
- 잔상 지속 시간과 속이기 성공 충전량은 `src/content/tuning.ts`에서 조정한다.

## 시간정지 궁극기

- 궁극기 충전량이 최대일 때 의미 입력 `ultimatePressed`를 받으면 충전량을 0으로 소비하고 `recording`을 시작한다.
- `recording`은 60Hz 기준 최대 10초 동안 유지하며 `ultimatePressed`를 다시 받으면 즉시 끝낸다. 적 AI·진형 인식·적 행동 타이머·재등장·적 HP·피격 상태와 기존 플레이어·적 투사체의 위치·수명은 갱신하지 않는다.
- 플레이어 이동·공격·순간이동·쿨타임은 정상 갱신한다. 기록 중 새로 발사한 플레이어 투사체는 별도 시간 영역에서 경로와 충돌을 계산하지만 화면에는 발사 위치에 정지한 상태로 표시하고 실제 적 상태는 바꾸지 않는다.
- 기록 시작 시 적 HP를 투영 상태로 복사한다. 롱소드와 플레이어 투사체의 예정 적중은 기록 프레임·대상·피해량만 큐에 넣으며 적중 표시를 만들지 않는다. 투영상 먼저 사망한 적은 이후 투사체 충돌 대상에서 제외해 후속 투사체가 그대로 진행한다.
- 매 기록 틱의 플레이어 위치·조준 방향, 롱소드 활성 여부·고정 조준 방향과 활·마법 투사체 위치를 순수 게임 상태 배열에 저장한다.
- 기록이 끝나면 실제 기록 프레임 수를 5로 나눈 올림값 동안 `replaying`으로 전환한다. 플레이어 입력과 세계 갱신을 모두 멈추고 저장한 위치·롱소드·활·마법 경로를 순서대로 표시하며, 각 재생 구간에 속한 적중 이벤트를 실제 적 HP와 사망 상태에 적용한다. 재생 피해는 압축 재생 자체를 멈추는 히트스톱을 추가하지 않는다.
- `replaying` 중 적 AI와 공격 상태는 갱신하지 않으며 presentation 계층에서 살아 있는 적의 조준 표시만 현재 재생 잔상을 향하게 한다.
- 재생이 끝나면 아직 경로가 남은 기록 시간 영역의 플레이어 투사체를 일반 시간 영역으로 옮기고 기록·적중 배열을 비운 뒤 `inactive`로 돌아가 최종 플레이어 위치에서 전투를 재개한다.
- 최대 기록 시간, 재생 배속과 최대 충전량은 `src/content/tuning.ts`에서 조정한다.

## 스킬 배치 UI

- 하단 스킬 바는 Q, E, R, Space와 마우스 오른쪽 버튼 슬롯을 항상 표시한다.
- Tab으로 스킬창을 열고 시간정지 또는 순간이동을 슬롯에 드래그해 배치한다.
- 스킬창이 열린 동안 `GameClock`에 렌더 델타를 전달하지 않아 전투 시뮬레이션을 정지하며, 닫을 때 정지 시간을 따라잡지 않는다.
- 한 스킬은 한 슬롯에만 존재하며, 사용 중인 슬롯으로 옮기면 두 스킬의 위치를 교환한다.
- 배치 정보는 게임 규칙 상태가 아니라 presentation 계층에만 둔다. 저장 기능은 아직 만들지 않는다.

## 롱소드 기본 공격

- 클릭한 시뮬레이션 틱의 조준 방향을 고정하고 정해진 프레임 동안 검선을 휘두른다.
- 화면에 표시하는 검선과 동일한 순수 TypeScript 선분 판정으로 적중을 계산한다.
- 무기별 동작이 검증되기 전에는 공통 `Weapon` 인터페이스나 스킬 시스템을 만들지 않는다.
- 사거리, 스윙 각도, 활성 프레임, 쿨다운과 검선 두께는 `src/content/tuning.ts`에서 조정한다.

## 원거리 기본 공격

- 활은 발사 틱의 조준 방향을 유지하는 빠른 직선 투사체다.
- 마법은 활보다 느리며, 발사 후 매 시뮬레이션 틱의 `aimTargetX`, `aimTargetY`를 향해 제한된 각속도로 회전한다.
- 한 번에 유도 마법 투사체 하나만 유지해 커서 조작의 의도를 명확히 한다.
- 모든 투사체는 안정적인 ID 순서로 갱신하고, 남은 프레임·적중·아레나 이탈로 제거한다.
- 활과 마법은 벽이나 기둥에 닿으면 제거하며, 궁병 화살에도 같은 규칙을 적용한다.

## 이동과 충돌

- 플레이어, 검병과 궁병은 원 충돌체로 시작한다.
- 아레나는 현재 화면과 같은 960×540 크기로 고정하고 사방에 두께가 있는 벽을 둔다.
- 내부에는 위치 선정과 사선 차단을 검증할 축 정렬 직사각형 기둥 두 개만 고정 배치한다.
- 플레이어와 적의 원 충돌체는 벽과 기둥을 통과하지 않으며, 대각 이동은 막히지 않은 축을 따라 미끄러진다.
- 살아 있는 적끼리는 각자의 AI 이동이 끝난 뒤 겹침을 해소하고, 틱의 모든 위치 갱신이 끝나면 플레이어를 포함한 살아 있는 액터 전체가 안정적인 배열 순서로 비겹침을 다시 보장한다. 정확히 같은 좌표에서는 플레이어 조준 방향 또는 고정 축을 사용하며, 지형에 막힌 쪽이 이동하지 못한 분량은 상대가 추가로 이동한다.
- 롱소드 검선과 각 적의 원 충돌체를 안정적인 ID 순서로 직접 비교한다.
- 플레이어 투사체는 적의 원 충돌체, 궁병 화살은 플레이어와 활성 순간이동 잔상의 원 충돌체와 직접 비교한다.
- 롱소드, 검병의 베기와 궁병의 예고선은 첫 기둥 또는 벽까지만 판정하고 표시한다.
- Phaser 물리 바디와 충돌 이벤트에 판정을 맡기지 않는다.

현재 기둥 배치는 직접 추적하는 적이 축별 충돌로 자연스럽게 미끄러지는지만 먼저 확인한다. 길찾기, 파괴 가능한 지형, 문, 절차 생성, 화면보다 큰 월드와 카메라 진행은 만들지 않는다.

정확한 이동 속도, 공격 거리, 공격 간격, 충돌 크기는 임시 값으로 두고 플레이테스트 후 확정한다.

## 렌더링

첫 화면은 도형만 사용한다.

- 플레이어: 원 또는 삼각형, 피격 점멸과 무적 표시
- 조준 방향: 짧은 선
- 검병: 바라보는 방향, 공격 예고와 HP를 읽을 수 있는 원형 임시 표현
- 궁병: 바라보는 방향, HP와 고정된 화살 경로의 잔상을 읽을 수 있는 원형 임시 표현
- 롱소드 공격: 실제 판정 방향의 검선과 지나온 스윙 범위
- 활: 진행 방향이 읽히는 짧은 직선
- 마법: 유도 경로를 조작하기 쉬운 원형 투사체
- 배경: 단색, 사방 벽과 두 개의 직사각형 기둥
- HUD: 현재·최대 HP, 궁극기 충전과 현재 시간정지·압축 재생 단계 및 피격 강조

플레이어 피격 시 약한 화면 흔들림 외의 애니메이션, 파티클, 카메라 효과와 외부 에셋은 기본 조작이 확정된 뒤 추가한다. 렌더 보간도 60Hz 상태 표시가 고주사율 화면에서 실제로 거슬릴 때 presentation 계층에만 추가한다.

## 테스트

첫 게임 로직 작업에서 필요한 테스트는 `GameClock`뿐이다. 이후 순수 로직을 추가할 때 해당 기능의 테스트를 함께 추가한다.

매 변경 후 전체 검증을 실행한다.

```bash
npm run verify
```

`verify`는 순서대로 `npm test`와 `npm run build`를 실행한다. GitHub와 Cloudflare 배포 환경도 같은 명령을 사용한다.

## 배포

- 정적 웹 빌드는 Cloudflare Workers Static Assets로 배포한다.
- `main`은 프로덕션, 그 외 브랜치는 외부 플레이테스트용 Preview로 사용한다.
- 배포 전 `npm run verify`가 반드시 통과해야 한다.
- 서버 기능이 필요해질 때까지 Worker 엔트리, 데이터 저장소와 `/api` 라우트를 만들지 않는다.
- 서버 자격 증명은 Cloudflare Runtime Secret에만 저장하고 클라이언트 빌드에 포함하지 않는다.
- 구체적인 최초 연결과 작업 흐름은 `docs/DEPLOYMENT.md`를 따른다.

## 나중에 확장할 때 지킬 경계

- 장비는 키가 아니라 슬롯 ID로 선택한다.
- 스테이지 해금은 실제 스테이지가 생길 때 선택 가능한 슬롯 구성과 함께 설계한다.
- 게임 상태에는 Phaser 객체를 저장하지 않는다.
- 적과 투사체는 안정적인 ID와 배열 순서로 업데이트한다.
- 랜덤이 생기면 `Math.random()` 대신 시드 기반 `Rng`를 추가한다.
- 멀티플레이 서버와 Spring Boot 연동은 기본 전투와 게임 방향이 확정된 뒤 별도 설계한다.

이 항목들은 미래 구현을 미리 만들라는 의미가 아니다. 현재 코드를 특정 입력 장치나 Phaser 객체에 묶지 말라는 경계다.
