# ECHO — Technical Constraints

이 문서는 첫 프로토타입부터 반드시 지켜야 하는 기술 경계만 정의한다. 아직 플레이로 검증하지 않은 게임 시스템의 상세 설계는 포함하지 않는다.

## 스택

- Node.js 22.12+
- TypeScript strict
- Vite
- Phaser 4.2.1
- Vitest
- 정적 웹 빌드

Phaser는 반드시 `4.2.1`로 정확히 고정한다. 설치와 스모크 테스트가 끝나기 전에는 게임 로직을 구현하지 않는다.

## 절대 규칙

1. 게임 로직은 60Hz 고정 타임스텝으로만 진행한다.
2. Phaser Arcade/Matter Physics를 사용하지 않는다.
3. Phaser는 presentation 계층에서 렌더링, 브라우저 입력, 카메라, 오디오와 이펙트만 담당한다.
4. 이동·공격·충돌 상태는 순수 TypeScript 데이터와 함수로 처리한다.
5. 액터는 키보드와 마우스를 직접 읽지 않고 `InputSource`만 받는다.
6. 플레이테스트로 조정할 게임필 수치는 `src/content/tuning.ts`에 둔다. 기술 상수는 담당 모듈에 이름을 붙여 둔다.
7. 네트워크, 저장소, 플랫폼 인터페이스는 실제로 필요해질 때까지 만들지 않는다.

## 첫 프로토타입 구조

처음부터 최종 폴더 구조를 만들지 않는다. 첫 동작에 필요한 파일만 생성한다.

```text
src/
  main.ts
  core/
    GameClock.ts
    GameClock.test.ts
    InputSource.ts
  game/
    GameState.ts
    archer.ts
    enemies.ts
    enemyState.ts
    longsword.ts
    playerDamage.ts
    projectiles.ts
    slow.ts
    teleport.ts
    terrain.ts
    updateGame.ts
  presentation/
    ArenaScene.ts
    PhaserInputSource.ts
    SkillBindings.ts
    SkillLoadoutUi.ts
  content/
    tuning.ts
```

- `core`와 `game`은 Phaser, DOM, 브라우저 이벤트를 import하지 않는다.
- `presentation`이 Phaser API를 담당한다. `main.ts`는 Phaser 부트스트랩과 의존성 조립만 하며 게임 규칙을 갖지 않는다.
- 실제 기능이 생길 때만 파일을 분리한다.

## 고정 타임스텝

Phaser의 렌더 프레임 경과시간은 `GameClock` 누적기에만 전달한다. 게임 업데이트는 `GameClock`이 생성한 고정 스텝으로 실행한다.

```ts
interface SimulationStep {
  frame: number;
  dt: number;
}
```

- 한 렌더 프레임에서 실행할 최대 catch-up 횟수를 제한한다.
- 탭 복귀 후 남은 과도한 누적시간은 버린다.
- `Date.now()`, `performance.now()`, `requestAnimationFrame` 델타를 게임 규칙에서 직접 읽지 않는다.
- 첫 테스트는 정상 프레임, 긴 프레임, catch-up 제한을 검증한다.

타격감용 히트스톱은 적중이 확정되면 대상의 상태에 남은 프레임 수를 기록한다. 롱소드는 공격자와 피격 대상을 함께 멈추고, 원거리 투사체는 피격 대상만 멈춘다. 해당 대상의 이동과 행동 타이머만 멈추며 `GameClock`, 시뮬레이션 프레임과 입력 샘플링은 계속 진행한다. 지속 시간은 `src/content/tuning.ts`에서 조정하고 네트워크나 범용 시간 시스템은 미리 만들지 않는다.

게임 메커니즘으로서의 슬로우도 시뮬레이션을 60Hz로 유지하고 결정론적인 게임 상태와 규칙으로 표현한다. 의미 입력이 유지되고 MP가 남아 있는 동안 활성화하며, MP 소모와 회복은 감속되지 않은 고정 `dt`로 계산한다. MP가 바닥난 뒤에는 입력을 놓아야 회복을 시작해 활성 상태가 빠르게 켜지고 꺼지는 현상을 막는다. 슬로우 중 플레이어 이동·공격 타이머는 정상 속도를 유지하고, 월드에 나온 투사체와 피격 대상 타이머에는 조정된 `dt`와 프레임 변화량을 사용한다. 시간 배율과 MP 수치는 `src/content/tuning.ts`에서 조정한다.

## 입력 모델

첫 프로토타입은 동작의 의미만 표현하고 실제 키는 어댑터가 결정한다.

```ts
interface InputFrame {
  moveX: number;
  moveY: number;
  aimTargetX: number;
  aimTargetY: number;
  primaryPressed: boolean;
  slowHeld: boolean;
  teleportPressed: boolean;
  weaponSlotPressed: 0 | 1 | 2 | null;
}

interface InputSource {
  sample(frame: number): InputFrame;
}
```

- `moveX`, `moveY`는 정규화된 이동 방향이다.
- `aimTargetX`, `aimTargetY`는 현재 커서의 게임 월드 좌표다. 플레이어 조준과 유도 마법의 회전은 게임 로직이 이 좌표에서 계산한다.
- `primaryPressed`는 브라우저 입력의 상승 에지를 어댑터가 보관했다가 다음 시뮬레이션 틱에서 한 번만 반환하고 즉시 비운다.
- `slowHeld`는 실제 키가 아니라 지속형 슬로우 사용 의도다. 어댑터가 현재 키 상태를 매 시뮬레이션 틱에 제공한다.
- `teleportPressed`는 커서 방향 순간이동을 시도하는 상승 에지다.
- `weaponSlotPressed`는 실제 숫자 키가 아니라 플레이테스트 슬롯 ID다. 실제 키 배정은 입력 어댑터에만 둔다.
- 한 렌더 프레임에서 여러 catch-up 틱이 실행되어도 클릭 한 번이 여러 공격으로 소비되면 안 된다.
- Q, E, R, Space와 마우스 오른쪽 버튼의 스킬 배치는 presentation 계층의 `SkillBindings`가 관리한다.
- 기본 배치는 Space에 슬로우, 마우스 오른쪽 버튼에 순간이동이며 Q, E, R은 비어 있다.
- 스킬창이 열린 동안 `PhaserInputSource`는 게임플레이 입력을 만들지 않는다.

이 형태는 나중에 로컬 입력을 녹화하거나 네트워크 입력으로 교체할 수 있게 하지만, 지금 리플레이나 네트워크 구현을 요구하지 않는다.

## 현재 게임 상태

첫 프로토타입 상태는 다음 정보만 가진다.

- 플레이어 위치와 조준 방향
- 플레이어의 현재·최대 HP와 MP
- 안정적인 ID와 종류를 가진 검병·궁병의 위치, HP, 조준 방향, 행동 단계와 피격 표시의 남은 프레임
- 선택한 무기 슬롯과 각 기본 공격의 쿨다운
- 롱소드 기본 공격의 고정 조준 방향과 남은 스윙 프레임
- 안정적인 ID, 종류, 위치, 속도와 남은 프레임을 가진 화살·마법 투사체
- 지속형 슬로우의 활성 상태
- 순간이동 목적지와 남은 쿨타임
- 현재 시뮬레이션 프레임

방패병과 마법사 상태, 장비 드롭, 스테이지 해금, 경험치, 층, 보스와 적응 통계 필드는 아직 추가하지 않는다.

## 검병

- 검병은 플레이어를 직접 추적하다 사거리 안에서 공격 방향을 고정하고 예고, 베기와 후딜레이를 순서대로 실행한다.
- 이동과 행동 타이머는 슬로우의 월드 시간 배율을 적용하며 히트스톱 중에는 모두 멈춘다.
- 베기는 화면에 표시한 고정 방향 선분과 플레이어의 원 충돌체를 직접 비교하고 한 공격에 한 번만 피해를 준다.
- 플레이어 공격은 무기별 임시 피해량만큼 검병 HP를 줄인다. HP가 소진된 검병은 짧은 월드 시간 뒤 재등장한다.
- 플레이어 HP가 소진되면 시작 위치와 최대 HP로 즉시 복귀하고 패배 횟수를 기록한다. 게임 오버 UI는 아직 만들지 않는다.

## 궁병

- 궁병은 플레이어와의 거리가 선호 구간보다 멀면 접근하고 가까우면 후퇴한다. 선호 구간 안에서는 이동을 멈추고 공격을 준비한다.
- 공격 준비를 시작한 틱의 방향을 고정하고 실제 화살 경로에 반투명 잔상을 표시한다. 준비 시간이 끝나면 플레이어 활과 같은 속도·수명의 직선 화살을 발사한다.
- 궁병 화살은 적 소유 투사체로 구분해 플레이어에게만 충돌하며, 플레이어 화살과 동일하게 슬로우의 월드 시간 배율을 적용한다.
- 발사 후에는 고정된 후딜레이를 거친 뒤 다시 거리 조절을 시작한다. 이동, 준비와 후딜레이는 히트스톱 중 멈춘다.
- 방패병과 마법사 행동은 만들지 않는다. 적 상태는 `kind`로 구분한 유니온과 안정적인 ID 배열로 갱신해 이후 실제 적 종류가 추가될 때 분기 하나를 확장할 수 있게 둔다.

## 순간이동

- 슬로우 활성 여부와 관계없이 커서 방향으로 순간이동할 수 있다.
- 이동 거리는 상한을 가지며 벽, 기둥과 살아 있는 적의 충돌체 내부에 착지하지 않는다.
- 기둥은 넘어갈 수 있지만 사방 벽 바깥으로 이동할 수는 없다.
- 쿨타임은 플레이어 행동 타이머이므로 슬로우의 영향을 받지 않고, 히트스톱 중에는 멈춘다.
- 롱소드, 활 또는 마법이 적에게 실제로 적중하면 남은 쿨타임을 0으로 초기화한다.
- 최대 거리와 기본 쿨타임은 `src/content/tuning.ts`에서 조정한다.

## 스킬 배치 UI

- 하단 스킬 바는 Q, E, R, Space와 마우스 오른쪽 버튼 슬롯을 항상 표시한다.
- Tab으로 스킬창을 열고 슬로우 또는 순간이동을 슬롯에 드래그해 배치한다.
- 한 스킬은 한 슬롯에만 존재하며, 사용 중인 슬롯으로 옮기면 두 스킬의 위치를 교환한다.
- 배치 정보는 게임 규칙 상태가 아니라 presentation 계층에만 둔다. 저장 기능은 아직 만들지 않는다.

## 롱소드 기본 공격

- 클릭한 시뮬레이션 틱의 조준 방향을 고정하고 정해진 프레임 동안 검선을 휘두른다.
- 화면에 표시하는 검선과 동일한 순수 TypeScript 선분 판정으로 적중을 계산한다.
- 무기별 동작이 검증되기 전에는 공통 `Weapon` 인터페이스나 스킬 시스템을 만들지 않는다.
- 사거리, 스윙 각도, 활성 프레임, 쿨다운과 검선 두께는 `src/content/tuning.ts`에서 조정한다.

## 원거리 기본 공격

- 활은 발사 틱의 조준 방향을 유지하는 빠른 직선 투사체다.
- 마법은 활보다 느리며, 발사 후 매 시뮬레이션 틱의 `aimTargetX`, `aimTargetY`를 향해 제한된 각속도로 회전한다.
- 한 번에 유도 마법 투사체 하나만 유지해 커서 조작의 의도를 명확히 한다.
- 모든 투사체는 안정적인 ID 순서로 갱신하고, 남은 프레임·적중·아레나 이탈로 제거한다.
- 활과 마법은 벽이나 기둥에 닿으면 제거하며, 궁병 화살에도 같은 규칙을 적용한다.

## 이동과 충돌

- 플레이어, 검병과 궁병은 원 충돌체로 시작한다.
- 아레나는 현재 화면과 같은 960×540 크기로 고정하고 사방에 두께가 있는 벽을 둔다.
- 내부에는 위치 선정과 사선 차단을 검증할 축 정렬 직사각형 기둥 두 개만 고정 배치한다.
- 플레이어와 적의 원 충돌체는 벽과 기둥을 통과하지 않으며, 대각 이동은 막히지 않은 축을 따라 미끄러진다.
- 롱소드 검선과 각 적의 원 충돌체를 안정적인 ID 순서로 직접 비교한다.
- 플레이어 투사체는 적의 원 충돌체, 궁병 화살은 플레이어의 원 충돌체와 직접 비교한다.
- 롱소드, 검병의 베기와 궁병의 예고선은 첫 기둥 또는 벽까지만 판정하고 표시한다.
- Phaser 물리 바디와 충돌 이벤트에 판정을 맡기지 않는다.

현재 기둥 배치는 직접 추적하는 적이 축별 충돌로 자연스럽게 미끄러지는지만 먼저 확인한다. 길찾기, 파괴 가능한 지형, 문, 절차 생성, 화면보다 큰 월드와 카메라 진행은 만들지 않는다.

정확한 이동 속도, 공격 거리, 공격 간격, 충돌 크기는 임시 값으로 두고 플레이테스트 후 확정한다.

## 렌더링

첫 화면은 도형만 사용한다.

- 플레이어: 원 또는 삼각형
- 조준 방향: 짧은 선
- 검병: 바라보는 방향, 공격 예고와 HP를 읽을 수 있는 원형 임시 표현
- 궁병: 바라보는 방향, HP와 고정된 화살 경로의 잔상을 읽을 수 있는 원형 임시 표현
- 롱소드 공격: 실제 판정 방향의 검선과 지나온 스윙 범위
- 활: 진행 방향이 읽히는 짧은 직선
- 마법: 유도 경로를 조작하기 쉬운 원형 투사체
- 배경: 단색, 사방 벽과 두 개의 직사각형 기둥
- HUD: 현재·최대 HP와 MP, 슬로우 활성 상태

애니메이션, 파티클, 카메라 효과, 외부 에셋은 기본 조작이 확정된 뒤 추가한다. 렌더 보간도 60Hz 상태 표시가 고주사율 화면에서 실제로 거슬릴 때 presentation 계층에만 추가한다.

## 테스트

첫 게임 로직 작업에서 필요한 테스트는 `GameClock`뿐이다. 이후 순수 로직을 추가할 때 해당 기능의 테스트를 함께 추가한다.

매 변경 후 전체 검증을 실행한다.

```bash
npm run verify
```

`verify`는 순서대로 `npm test`와 `npm run build`를 실행한다. GitHub와 Cloudflare 배포 환경도 같은 명령을 사용한다.

## 배포

- 정적 웹 빌드는 Cloudflare Workers Static Assets로 배포한다.
- `main`은 프로덕션, 그 외 브랜치는 외부 플레이테스트용 Preview로 사용한다.
- 배포 전 `npm run verify`가 반드시 통과해야 한다.
- 서버 기능이 필요해질 때까지 Worker 엔트리, 데이터 저장소와 `/api` 라우트를 만들지 않는다.
- 서버 자격 증명은 Cloudflare Runtime Secret에만 저장하고 클라이언트 빌드에 포함하지 않는다.
- 구체적인 최초 연결과 작업 흐름은 `docs/DEPLOYMENT.md`를 따른다.

## 나중에 확장할 때 지킬 경계

- 장비는 키가 아니라 슬롯 ID로 선택한다.
- 스테이지 해금은 실제 스테이지가 생길 때 선택 가능한 슬롯 구성과 함께 설계한다.
- 게임 상태에는 Phaser 객체를 저장하지 않는다.
- 적과 투사체는 안정적인 ID와 배열 순서로 업데이트한다.
- 랜덤이 생기면 `Math.random()` 대신 시드 기반 `Rng`를 추가한다.
- 멀티플레이 서버와 Spring Boot 연동은 기본 전투와 게임 방향이 확정된 뒤 별도 설계한다.

이 항목들은 미래 구현을 미리 만들라는 의미가 아니다. 현재 코드를 특정 입력 장치나 Phaser 객체에 묶지 말라는 경계다.
